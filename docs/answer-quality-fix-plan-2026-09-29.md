# Al-Bayan answer quality fix plan

**2026-09-30 checkpoint:** Live answers use `AnswerV2`, and bare source-only answers are replaced by `no_summary`. The prepared inventory is 44 files; all 44 pass the strict converter and content audit in Arabic, English and German, and all 37 remaining scholar excerpts match the linked official pages exactly. Every changed answer remains a draft with no matching approval hash. The loader now preserves numbered-list citations, and known unresolved music and tawassul rulings fail closed until a reviewed view decision exists. The full live evaluation produced 56 displayed answers, all with valid AnswerV2, zero source-only answers, and zero wrong sources among reviewed cases; it also recorded five Gemini 503 responses and one timeout. Its refusal percentage is not final because 15 obsolete two-surah refusal labels were corrected afterward. Focused gold and repentance runs passed 3/3, and tawassul refused safely 3/3. Live German conversion is still variable and often returns the safe `no_summary` result, so the 95% live required-point target and Mo acceptance remain open. Internal review still requires an enable flag and private key, public prepared publishing remains off, and no database or approval decision was changed by this repair.

**Review rule:** Mo reviews answers during development. An answer gets the “Scholar reviewed” label only after a scholar has actually reviewed it. Scholar review comes later, when Mo stops finding substantive mistakes.

| Phase | Weakness | Fix and check before moving on |
|---|---|---|
| 1. Measure answer quality | The current test mostly counts answers and refusals. It can miss a wrong or incomplete answer that passes the checker. | Add *must contain* points and *must not confuse* traps to the test questions. Include gold zakat rate versus threshold, why five prayers, mercy and Hell, repentance steps, and conversion. Score clarity, completeness, source support and accuracy separately. Use a focused set during each fix, then the full set at milestones. |
| 2. Understand the question | The first step can change what was asked. It turned “how much zakat is due” into the minimum threshold and treated a general conversion question as a personal case. | Keep each requested point distinct, reject points the visitor did not ask for, and narrow the personal-case rule. Check the question frame against the original wording before searching. |
| 3. Find the right sources | Word matching returns verses that merely mention a topic, while short hadith titles and the first scholar-search hits can hide better evidence. | Build checked topic-to-source maps for common questions. Search more candidates, then rank them by the exact requested point and surrounding context. Test Quran, hadith and scholar search separately. Investigate tafsir, fuller hadith search and more scholar material, but add none until its display, storage and AI-use rights are clear. |
| 4. Write a useful answer | Four short facts often give too little explanation or repeat one point. | Build answers with a direct answer first, then relevant evidence, an attributed scholar explanation, and any conditions or exceptions that change the answer. Allow more cited sentences when the question needs them. Keep Quran and hadith text supplied by their sources, never retyped by AI. |
| 5. Check the whole answer | The checker can pass a cited answer that misses the requested number or gives only one of several needed steps. Copy checks can also discard useful wording. | Require the direct answer to contain the requested rate, number, reason or steps. Reject repetition and off-target evidence. Refine copy detection with examples that protect exact Quran and hadith text while allowing clear paraphrases. If no checked summary survives, show an honest no-summary message; never present bare passages as the answer. |
| 6. Handle disagreement and consistency | Ask has no working other-views display or published answer packages. Repeated questions get changing detail. Search results from a small, uneven quote library cannot establish a scholarly majority. | Put clearly supported other views in a closed fold. Use a reviewed view decision for common disputed questions; where there is no such decision, show the sourced views side by side without naming a winner. Prepare stable answer packages for common general questions, fix their missing question types, and recheck their sources. Never cache a personal question as a public answer. |
| 7. Improve the reading experience and cost data | English and German readers see Arabic-only scholar quotes. The chat looks conversational but sends each question alone. Actual token cost is not recorded. | Give clearly labelled, checked translations where rights allow. Make it clear that each question is independent until safe follow-up handling exists. Record time, token use and retries by pipeline step without logging visitors’ questions. Keep the current Lite models unless a comparison proves a stronger model improves difficult answers enough to justify its price. |
| 8. Mo’s acceptance pass | Passing automatic tests cannot establish religious accuracy or whether an answer feels helpful. | Mo reviews the focused questions and repeated runs in Arabic, English and German. Fix every substantive mistake he finds, then run the full test set. Aim for no wrong core numbers, altered scripture, invented sources or unsupported rulings; at least 95% of required points present; and stable core answers across three runs. Only after Mo is satisfied should a scholar be invited to experience and review the product. |

**Partial answers:** When approved sources explain only part of a “why” question, show that sourced part and clearly say what the sources did not establish. Do not invent the missing reason or present a partial explanation as complete.

**Rights investigation:** Review each source’s terms, existing rights record and any permission reply. Mark its proposed use as allowed, unclear or disallowed. Continue improving answers with the currently approved material while unclear uses remain blocked.
