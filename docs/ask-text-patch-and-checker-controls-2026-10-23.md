## Retained repair

Previously, a correction for copied wording regenerated the entire claim, including source IDs and the concern label. The recorded worship correction changed a hadith claim's concern from R2 to unsupported R1 and the section failed validation.

For eligible copying-only patches the writer now returns only text under code-assigned keys such as P1. The full provider contract forbids reference fields, concern fields and unrequested patch keys. The server reconstructs the original claim with the replacement text and preserves all identities and untouched wording. Full original-source, context, qualification, coverage and final consistency checking still run. Invalid patch envelopes fail as a whole. This is a shared correction mechanism; it contains no religious-topic answers or exceptions.

Source groups needing substantive support repairs still use the ordinary bounded correction path. The text-only mechanism does not claim to repair unsupported meaning or invalid metadata in an initial draft. It adds no paid calls or retries.
