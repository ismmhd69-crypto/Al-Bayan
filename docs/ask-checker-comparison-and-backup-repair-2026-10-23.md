## 3. Demonstrated backup routing defect and repair

The first comparison made ten Mistral requests. Every one received an explicit HTTP 404 rejection before generation, with **$0 cost** and no generation ID. These are technical failures, not semantic answers or evidence that the model cannot understand Arabic. The initial runner's global consecutive-error counter reset between Gemini successes; consequently all ten unavailable-backup requests were attempted. No paid or uncertain request was automatically retried.

Read-only inspection of the current official model metadata showed four endpoints for the pinned Mistral model, including four in the ZDR endpoint listing. None advertised `reasoning`. Bayan nevertheless sent `reasoning: {effort: low, exclude: true}` together with `provider.require_parameters=true`. OpenRouter documents that this routing setting requires providers to support all requested parameters. See [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection) and [ZDR endpoint metadata](https://openrouter.ai/docs/api/api-reference/endpoints/list-endpoints-zdr).

**Implemented:** omit that unsupported optional parameter for the exact pinned non-reasoning Mistral model. Other models retain their existing reasoning behavior. Strict schema validation, `require_parameters`, `zdr`, `data_collection=deny`, price ceilings, output allowances, provider identities and model chains remain unchanged. This is model capability handling, not a question/topic-specific answer exception.

**Offline verified:** a strict mock endpoint rejects the unsupported option and accepts the corrected request while retaining every privacy/schema gate. Separate whole-request fingerprint reconstruction matched **all ten old and ten new request fingerprints**: adding back only the old reasoning field reconstructs each exact rejected request. Removing only it reconstructs each exact successful request. No paid call was made by this identity verifier.

**Live verified:** after the request repair, the same backup answered all ten exact-bank cases under the unchanged privacy and strict-output settings. The repaired run would stop immediately on a new backup transport/format failure. Prior Gemini responses were reused for comparison analysis rather than paid for again. The one-variable change and exact request identities support this routing diagnosis, without claiming future provider availability.
