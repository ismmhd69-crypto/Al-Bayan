# Local meaning-model connection

Status: prepared and tested with invented responses only. No model is selected, installed, downloaded or approved. No real source embeddings or live model queries were generated by this work.

## What it connects

`lib/ask/search-engine/local-embeddings.ts` implements Hugging Face Text Embeddings Inference's `/info` and batched `/embed` protocol. It supplies both the index builder's `SourceEmbedder` and the retrieval engine's `QueryEmbedder`. The actual local corpus adapter can use it when explicitly enabled. This does not implement a production vector database or hosted inference service.

The adapter accepts only an explicit `http://127.0.0.1:<port>` origin with no credentials, path, query or fragment. Redirects are refused. It has no default model, automatic download, external fallback, provider key or retry. The proposed model must already be served by an independently prepared and pinned local TEI deployment.

Primary protocol references checked on 20 October 2026:

- [TEI inference and batching](https://huggingface.co/docs/text-embeddings-inference/en/quick_tour).
- [TEI model/server information fields](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/lib.rs).
- [Embedding request fields](https://github.com/huggingface/text-embeddings-inference/blob/main/router/src/http/types.rs).

These moving documentation pages explain the protocol, not a verified deployment. Runtime configuration pins the actual model revision and server version/build.

## Configuration contract

`ASK_LOCAL_EMBEDDINGS` remains false/unset by default. When explicitly true, `ASK_LOCAL_EMBEDDING_CONFIG` must contain a JSON object with exactly these fields:

| Field | Meaning |
|---|---|
| `endpoint` | Explicit loopback HTTP origin, such as `http://127.0.0.1:8080` |
| `model` | Candidate's canonical `organisation/model` identity |
| `revision` | Exact 40-character lowercase model commit, never `main` |
| `dimensions` | Expected native output dimensions, 1 through 8192 |
| `queryPrefix` | Explicit query instruction/prefix, possibly empty, chosen from the model's documented usage |
| `passagePrefix` | Explicit passage instruction/prefix, possibly empty |
| `pooling` | Exact deployment pooling, one of `cls`, `mean`, `last-token` |
| `dtype` | Exact deployment precision: `float16`, `float32` or `bfloat16` |
| `serverVersion` | Exact TEI version |
| `serverSha` | Exact 40-character lowercase TEI build commit reported by the deployment |
| `deploymentRecipe` | 64-character SHA-256 of the reviewed deployment recipe, including image/weights/tokenizer/config fingerprints and no implicit default prompt |

The JSON contains no secrets. Configuration is server-only and must not use a `NEXT_PUBLIC_` variable. It is rejected outside the existing local development runtime, even if flags are accidentally supplied to a deployed website.

The identity is checked through `/info` before each batch and again after embedding. Auto truncation must be false; model ID/revision, server identity, precision, pooling and batch capacity must agree. The server information is an operator-controlled report. In TEI, `model_sha` reports the launch revision; it is not independent cryptographic verification of the loaded weights. TEI's `/info` also does not expose its implicit default-prompt configuration. Consequently the reviewed deployment recipe and actual deployment inspection remain mandatory. Supplying an arbitrary hash does not prove that inspection happened.

The adapter applies the explicit prefix and submits the original without trimming, translating, combining or shortening it. It requests `truncate:false`, `normalize:true` and no named server prompt. The TEI deployment must have no implicit default prompt. Inputs exceeding the model's token limit fail rather than become shortened evidence. The adapter bounds each batch to 16 inputs, each input to 24,000 characters, the request to 512,000 bytes and the response to 4,000,000 bytes. A 30-second bounded transport respects the research cancellation signal. These are operational caps, not a claim that every candidate supports that token/character length.

Vectors must match the batch count and dimensions, contain finite numbers and be nonzero. Failure responses are not logged or returned as source text. Only fixed error codes escape. A failed request is not automatically retried.

## Consistent index identity

The vector-space contract now includes an optional `recipe` fingerprint. New adapters calculate it from the explicit prefixes, pooling, precision, normalisation/truncation settings, server version/build and deployment-recipe hash. Query and passage vectors must match model, revision, dimensions and this recipe. Changing a prefix or deployment recipe requires a new compatible index generation. Existing legacy vector fixtures without a recipe remain mutually compatible; they cannot silently match this new adapter.

The local filesystem index still requires current source/rights revalidation before returning candidates. An eligible semantic generation is required unless the separate lexical-only preview is explicit. A lexical-only generation never triggers embedding merely because a provider is configured.

## Gates before any real model pilot

1. Reconcile the existing evaluation reservation; preserve the shared spending record and agree the experiment cap.
2. Review the candidate's license, hardware/hosting costs, multilingual capabilities and input recipe. Choosing a protocol adapter does not choose a winning model.
3. Verify source-specific embedding capability. Current real export receipts still set this false where it has not been established. Do not manually flip a real passage's permission flag or repurpose ordinary publication approval.
4. Prepare a frozen reviewed question/source sample with qualifications, paraphrases and held-out examples in all three languages.
5. Inspect the actual pinned deployment, weights/tokenizer and no-default-prompt launch recipe. Nothing in this implementation launches Docker or downloads a model.
6. Build a small permission-eligible index through the existing `buildSearchIndex` interface with this adapter. Keep exact source bytes and hashes; publish an immutable generation only after checks. The command for the earlier lexical pilot still builds a lexical-only index and has not been relabelled semantic.
7. Compare actual multilingual retrieval and ranking, document misses/false positives/cost, and keep production off pending acceptance. Persistent production vector storage, deployed indexing/cleanup, privacy, accounting and operations remain separate work.

## Evidence so far

Offline checks exercise model identity drift, encoding recipe mismatch, exact source preservation, malformed vectors, explicit no truncation, cancellation, redirect/error isolation and permission rejection before requests. An actual loopback HTTP server with invented vectors confirms wire framing. An actual private index generation plus mocked model transport passes through `localCorpusRetriever`, produces a semantic discovery hit, restores the complete invented parent, and stops issuing embedding queries after current source eligibility is revoked. These tests prove connection mechanics and isolation. They establish no real model quality, source faithfulness, multilingual recall or release readiness.
